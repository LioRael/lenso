# Native Rust Module recipe

Use this branch for a Module compiled into the App binary as an ordinary Cargo
dependency. App Composition still decides whether the linked package becomes a
Module Instance.

## 1. Find the live API

Read the selected versions in `Cargo.toml` and `Cargo.lock`, then inspect these
symbols in the installed dependency source:

- `lenso_native_adapter::{NativeModuleFactory, NativeModuleFactoryContext,
  NativeModuleInstance, NativeModuleRegistry}`;
- `lenso_kernel::{ModuleLifecycle, PrepareContext, ActivateContext,
  DeactivateContext, ModuleDependencies}`; and
- the generated Capability Provider, Endpoint, Client, request/response, Domain
  Error, `CAPABILITY_ID`, and `DESCRIPTOR_VERSION` symbols.

The current reference implementations are `lenso-secrets-env-module` in
`LioRael/lenso-secrets-module`, `lenso-otel-module` in
`LioRael/lenso-otel-module`, and the Web Ingress/Egress Modules in
`LioRael/lenso-web`. Treat those repositories and the selected crate versions
as the source of truth when this example differs.

## 2. Create the package

A small provider-only package normally needs:

```text
crates/greeting-module/
├── Cargo.toml
├── src/lib.rs
└── tests/module.rs
```

Depend on the Capability contract crate, `lenso-kernel`,
`lenso-native-adapter`, and only the libraries the Module itself owns. The App
binary depends on the Module crate and registers its factory.

## 3. Implement the generated Provider and factory

This is the minimum request-provider shape. `greeting_contract` represents a
contract crate generated by `lenso-contract-codegen`.

```rust,ignore
use std::rc::Rc;

use futures::future::{self, LocalBoxFuture};
use greeting_contract::{
    GreetError, GreetRequest, GreetResponse, GreetingEndpoint,
    GreetingInvocationError, GreetingProvider,
};
use lenso_kernel::{InvocationContext, NativeRequestEndpoint, RuntimeFailure};
use lenso_native_adapter::{
    NativeModuleFactory, NativeModuleFactoryContext, NativeModuleInstance,
};

pub const PACKAGE_ID: &str = "example.greeting";
pub const PACKAGE_VERSION: &str = env!("CARGO_PKG_VERSION");

#[derive(Clone, Debug, serde::Deserialize)]
#[serde(deny_unknown_fields)]
struct GreetingConfig {
    prefix: String,
}

#[derive(Clone, Debug)]
struct Greeter {
    prefix: String,
}

impl GreetingProvider for Greeter {
    fn greet(
        &self,
        _context: InvocationContext,
        request: GreetRequest,
    ) -> LocalBoxFuture<'static, Result<GreetResponse, GreetingInvocationError>> {
        let result = if request.name.trim().is_empty() {
            Err(GreetingInvocationError::Domain(GreetError::EmptyName))
        } else {
            Ok(GreetResponse {
                message: format!("{} {}", self.prefix, request.name),
            })
        };
        Box::pin(future::ready(result))
    }
}

#[derive(Clone, Debug, Default)]
pub struct GreetingFactory;

impl NativeModuleFactory for GreetingFactory {
    fn package_id(&self) -> &'static str {
        PACKAGE_ID
    }

    fn package_version(&self) -> &'static str {
        PACKAGE_VERSION
    }

    fn instantiate(
        &self,
        context: NativeModuleFactoryContext<'_>,
    ) -> Result<NativeModuleInstance, RuntimeFailure> {
        if context.entrypoint() != "default" {
            return Err(RuntimeFailure::InvalidResolvedPlan {
                detail: format!("unsupported greeting entrypoint {}", context.entrypoint()),
            });
        }
        let config = serde_json::from_str::<GreetingConfig>(context.configuration())
            .map_err(|error| RuntimeFailure::InvalidResolvedPlan {
                detail: format!("invalid greeting configuration: {error}"),
            })?;
        let endpoint = Rc::new(GreetingEndpoint::new(Greeter {
            prefix: config.prefix,
        })) as Rc<dyn NativeRequestEndpoint>;
        Ok(NativeModuleInstance::new(vec![endpoint]))
    }
}
```

The registry matches `package_id()` and, when selected, `package_version()`.
It passes the App-local Instance key, selected entrypoint, and canonical opaque
configuration to every new generation. Validate all three when the package
supports multiple modes.

Use `NativeModuleInstance::with_endpoints`, `with_stream_endpoints`,
`with_event_endpoints`, or `with_all_endpoints` when the Capability interaction
kinds require them. The Instance endpoint set must exactly satisfy the Plan.

## 4. Add lifecycle and dependencies only when needed

Endpoint-only Modules use the no-op lifecycle supplied by
`NativeModuleInstance::new`. A Module with resources or managed work returns a
fresh lifecycle object from every `instantiate` call:

```rust,ignore
#[derive(Debug)]
struct WorkerLifecycle;

impl ModuleLifecycle for WorkerLifecycle {
    fn prepare(&self, context: PrepareContext) -> ModuleFuture {
        // Parse/check configuration and reserve reversible resources here.
        Box::pin(future::ready(Ok(())))
    }

    fn activate(&self, context: ActivateContext) -> ModuleFuture {
        // Build generated clients from context.dependencies(), then register
        // work through context.tasks().spawn_local(...). Pass
        // context.readiness() to ingress/background work that must wait.
        Box::pin(future::ready(Ok(())))
    }

    fn deactivate(&self, context: DeactivateContext) -> ModuleFuture {
        // Close Module-owned resources; Kernel cancels and joins managed tasks.
        Box::pin(future::ready(Ok(())))
    }
}
```

Construct generated consumers with `Client::from_dependencies` or the typed
`one`, `optional`, `many`, stream, and event accessors on
`ModuleDependencies`. The lifecycle context is the supported dependency path;
there is no global Capability registry.

## 5. Register and compose

The Runner makes the linked factory available:

```rust,ignore
let native = NativeModuleRegistry::new().with_factory(GreetingFactory);
let adapters = ExecutionAdapterCatalog::single(native);
```

Static registration is only availability. App Composition must still select a
Module Instance whose package identity/revision matches the factory and must
declare every endpoint, requirement, and binding. Continue with
`lenso-app-composition` for that project edit.

## Completion

This branch is complete when a fresh factory generation parses configuration,
exposes the exact selected endpoints, obtains dependencies only from lifecycle
context, cleans up managed work, and passes one real Plan-driven invocation.
