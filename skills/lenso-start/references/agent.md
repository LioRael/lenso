# Agent task map

Use this map for a result produced through an Agent Turn. Agent work combines
maintained product behavior, App configuration, and bounded Host mechanics; it
does not create a second composition authority.

## Inspect the maintained product first

Read the current `lenso-agent-harness` instructions, CLI `--help`, Agent Home,
Host Catalog, active Profile, Session backend, Tool inventory, and the real
headless or interactive fixture nearest the request. Use
<https://lenso.dev/docs/agent> as the journey map, then verify exact behavior in
the selected source revision.

## Choose the first owner

| Needed result | Primary Skill |
| --- | --- |
| Add or change one Tool, Context Source, Surface, policy, or other removable Agent behavior | `lenso-plugin-authoring` |
| Add or evolve the typed role used by that behavior | `lenso-capability-authoring` |
| Select Profiles, Tools, MCP servers, Session presentation, or other visible App differences | `lenso-app-configuration` |
| Change child-process, model transport, Session/Generation control, lane, or Host execution mechanics | `lenso-runtime-extension` |
| Decide ownership of prompts, memory, state, authorization, or delegation policy | `lenso-business-planning` |

Profiles and direct configuration narrow the maintained Host; they do not
expand Host policy. An MCP server contributes Tools or Context through its
selected Plugin path; it does not become an ambient registry. A child Agent is
a bounded parent-controlled task with explicit authority and durable Session
identity, not an independent hidden App. Session history and context compaction
are distinct from cross-Session product Memory.

## Complete one real Turn

1. Inspect the effective Profile, Tool and Context inventory, Session backend,
   and provenance before editing.
2. Make the smallest owned Plugin or Plugin Root change.
3. Run one real Turn that exercises the new behavior and one honest failure.
4. Verify tool grants, context provenance, Session durability, cancellation,
   and child authority where affected.
5. Restart or reopen the maintained Host when durability is claimed.
6. Disable or remove the optional behavior and prove the remaining Agent still
   starts with the expected inventory.

The Agent path is complete when a real Turn provides inspectable Session and
Tool/Context evidence, and the change can be removed without leaving hidden
authority or state.
