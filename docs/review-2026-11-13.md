# SDK design review — 2026-11-13

Scope: the complete local TypeScript and Rust SDKs, their public package boundaries and their native examples. The repository had no commits at review start, so this is a source review rather than a comparison against a commit. The governing specification is [Lenso product design v0.2, section 5](https://chatgpt.com/space/page_8d106197e7e08191b3a2ef80dee240e7).

## Verdict

The original implementation covered a useful native execution and SQLite persistence foundation, but its completion claim exceeded the evidence. Several SDK responsibilities were represented by interfaces or metadata while authors still had to implement the mechanisms themselves. This was most apparent in TS, where each Action repeated generic DTO annotations and external decoding, and Event/Console integration maintained additional hand-written wiring.

The review fixes mechanisms and their demonstrated authoring paths. It does not turn metadata into another execution runtime, require schemas for every native operation, add a universal ORM or move the Console application into the SDK repository.

## Correctness and delivery findings

- **P2 — Unowned asynchronous record completion.** A TS async callback matched the old `void` sink type but its Promise was discarded. Execution now awaits the declared sink. The sink remains an explicitly infallible observability hook, not transactional auditing. Regression coverage holds a record write pending and proves the call cannot finish early.
- **P2 — Output invariant failures could appear as access denials.** A validator returning/throwing `forbidden` was propagated as if authorization failed. Both implementations now classify output invariant failure as `internal`, preserving its private cause. Shared native/external action fixtures cover it.
- **P2 — Fresh-checkout type checking depended on stale declarations.** Root checking now builds package declarations in dependency order rather than relying on old `dist` output. It was exercised after deleting generated distributions.
- **P2 — Package verification depended on a new registry resolution.** Consumer verification now packs the installed dependency and SDKs, installs archives offline, checks valid and invalid typed calls, and executes their native imports. SDK `prepack` hooks prevent producing distributions without a build.

The TypeScript simplification keeps one owner for schemas and removes the duplicated credentials decoder and management handler table. Dynamic invocation is confined to external operation bindings; native business calls retain their original interfaces. Public calls and task submission infer contracts from the definitions, so supplying another argument cannot widen the inferred input or resource contract. The small structural parser interface accepts existing validators rather than introducing a schema DSL.

## Native Rust choices retained

- Native Actions still have no serde bounds. Serialization is introduced at JSON management interfaces and durable storage.
- Database clients, connection ownership, Drop and explicit asynchronous cleanup remain native; no erased resource container or shared cross-language host is required.
- Lease fencing, idempotency keys and native transaction integration remain explicit. The SDK does not imply exactly-once effects or cross-resource transactions.

These choices follow the product's native-language requirement and the Rust API/error/lifecycle principles used in the review. Runtime failures and missing product mechanisms were prioritized over stylistic rewrites.

## Verification and remaining scope

The [verification record](verification.md) lists executed commands and environments. Regression coverage includes schema inference and normalization, lazy policy failure behavior, resource startup/cleanup, duplicate subscription lifetimes, transactional event fanout, task attempt history, numeric limits, Console detail/custom operations and compiled page registration.

The independent Console application, built-in UI components, real mail providers, additional storage providers, production Auth administration, browser/platform execution and minimum-Rust-version validation remain separate work. This review does not claim those planned product capabilities are complete. No remote CI run, release or deployment is claimed.
