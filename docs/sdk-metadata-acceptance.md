## Real HTTP evidence

The [TypeScript report](sdk-metadata-acceptance/typescript.json) and [Rust report](sdk-metadata-acceptance/rust.json) are generated by the passing integration fixtures after server/database cleanup. They contain the actual returned Module and public error, platform facts, asserted checks and database effect counts. Regenerate with:

```sh
npm run build
cargo build --locked --manifest-path rust/Cargo.toml --workspace
LENSO_METADATA_REPORT_DIR=.local/sdk-metadata npm run test:integration
```

Each backend starts on an ephemeral port with a fresh SQLite database and real identities. Acceptance establishes:

- The native Module fixture, protected HTTP manifest, Console client and thin Agent consumer share one description. Legacy Actions remain unknown, and an explicit empty effects list remains distinct.
- Reading descriptions invokes no project Action and creates no project rows. Unauthorized discovery is denied.
- Malformed JSON yields a root format issue. Invalid fields yield declared field paths. Private input, unknown keys, native causes and stacks are absent from public failures; Console preserves the HTTP issue contract.
- A reader remains forbidden from creating despite advertised capabilities. Denied/invalid calls leave zero project rows.
- One authorized call normalizes its input, creates one persisted project, returns a result that is independently read back, and records exactly one successful create.

The fixtures use a generic SDK descriptor consumer and the existing HTTP Action route. They do not test an LLM or a separate MCP transport. Full browser regressions exercise the existing host against both backends; they do not constitute a physical Safari/iPhone run. Rust MSRV, Linux and Windows execution for this batch remain unverified locally. Auth/Files module annotations in the separate modules repository are outside this batch.
