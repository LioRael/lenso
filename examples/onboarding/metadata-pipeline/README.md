# Synthetic metadata pipeline

Two independently selected native business Plugins process invented filenames
and byte counts. A third, independent health Plugin exposes `GET /health` so
that the Host remains observable after business behavior is removed. No file
content is opened, uploaded, or stored.

- `example.metadata-normalizer` owns filename validation, whitespace trimming,
  extension normalization, and nonnegative byte counts. It provides
  `example.metadata@1`, version `1.0.0`.
- `example.metadata-summary` owns the `POST /metadata/summary` entrypoint,
  batch limits, and aggregation. Its required `Port<MetadataClient>` invokes
  the normalizer through the resolved Plan. It never calls the provider's Rust
  implementation directly.

The contract descriptor and JSON Schemas live in the independent
`contracts/metadata/` crate. Its checked Rust projection is generated by the
framework code generator and loaded with `include!`, matching the repository's
Capability crates. This keeps generated code outside rustfmt traversal while
the contract's build script checks freshness. Both business Plugins
are stateless and own no background tasks or external resources.

## Build and run

This is a **source-workspace example**. It uses the candidate workspace's native
Host and local dependencies; it is not evidence that a published CLI or registry
template can complete this composition.

From the repository root, using its pinned toolchain:

```sh
CARGO_BUILD_JOBS=2 cargo build --locked -p lenso-onboarding-metadata-pipeline
target/debug/lenso-onboarding-metadata-pipeline
```

The Host prints an ephemeral loopback address. Send only synthetic metadata:

```sh
curl -sS http://127.0.0.1:PORT/metadata/summary \
  -H 'content-type: application/json' \
  -d '{"files":[{"name":" report.PDF ","size_bytes":1024}]}'
```

The result contains normalized records, record count, total bytes, and counts by
extension. Invalid filenames or negative sizes produce a typed Domain Error
mapped to HTTP 422. Up to 100 records are accepted; an empty batch returns zero.
Unknown HTTP input fields are rejected by strict deserialization.

## Inspect, remove, and verify

```sh
target/debug/lenso-onboarding-metadata-pipeline --inspect
target/debug/lenso-onboarding-metadata-pipeline --without-normalizer
target/debug/lenso-onboarding-metadata-pipeline --without-summary --inspect
python3 examples/onboarding/metadata-pipeline/smoke.py
```

`--without-normalizer` must exit nonzero before listening because the selected
summary Plugin's required Capability is missing. `--without-summary` starts a
new Host with the normalizer and health Plugins selected; the summary Plugin is
absent from the Plan, its former route returns 404, and `/health` still returns
200. These flags change this custom
Host's selection. They are not live reconfiguration or a `lenso plugins remove`
command. Generated registration makes a Plugin available but never silently
reselects a removed Instance.

The smoke script launches real native Hosts, makes real loopback HTTP requests,
checks the derived Plan, exercises valid and invalid metadata, proves failed
startup without the required provider, verifies removal, and shuts each Host
down. It uses Python's standard library and accepts an optional binary path.

Regenerate after intentionally changing the contract, then rebuild; the contract's `build.rs`
rejects projection drift:

```sh
cargo build --locked -p lenso-contract-codegen --bin lenso-contract-codegen
target/debug/lenso-contract-codegen generate \
  examples/onboarding/metadata-pipeline/contracts/metadata/capability.json \
  --rust-runtime examples/onboarding/metadata-pipeline/contracts/metadata/runtime.rs
```
